# ClassSeat Manager — Master Specification

## 1. Project Overview

ClassSeat Managerは、高等学校教員が授業中に使用する、オフラインファーストの授業管理Webアプリケーションである。

主な目的は、以下を一つのシステムで管理することである。

* 授業
* クラス
* 生徒
* 席図
* グループ活動
* 条件付き席替え
* ランダムグループ編成
* 出欠
* 授業中の評価
* 生徒履歴
* 教師メモ
* 時間割
* A4横印刷
* CSV入出力
* バックアップ／復元

---

# 2. Target Environment

## 2.1 Primary Environment

* Windows PC
* Webブラウザ
* 完全オフラインで利用可能
* 外部サーバーへの接続を必須としない

## 2.2 Future Compatibility

将来的にiPad等のタブレットでも利用できるよう、レスポンシブなUI設計を採用する。

MVPではWindows PCを最優先する。

---

# 3. Core Design Philosophy

## 3.1 LessonSession First

システムの中心概念は「クラス」ではなく「実際に行われた授業」である。

1回の授業をLessonSessionとして管理する。

LessonSessionには以下を関連付ける。

* 参加生徒
* 席配置
* グループ
* 出欠
* 評価
* 教師メモ
* 授業日時
* 時限

---

## 3.2 Class and Course Separation

ClassとCourseを分離する。

Classは生徒の所属を表す。

Courseは授業・科目・選択授業を表す。

例えば、

* 1年1組
* 1年2組
* 1年3組

というClassが存在し、

「情報探究」というCourseに、

* 1年1組の生徒5名
* 1年2組の生徒8名
* 1年3組の生徒7名

が参加できる。

---

## 3.3 Student ID

出席番号を主キーとして使用しない。

システム内部ではUUID等の一意なStudent IDを使用する。

表示上は、

* 出席番号
* 氏名

を使用する。

---

## 3.4 Historical Integrity

過去の授業履歴は、現在の設定変更によって変更されてはいけない。

例えば、

2026/08/18
山田 → 5番席

2026/08/25
山田 → 18番席

となった場合、

2026/08/18の履歴には5番席が残る。

---

# 4. School Year

年度を管理する。

例：

* 2026年度
* 2027年度
* 2028年度

過年度データを破壊せず、新年度を作成できる。

---

# 5. Class Management

担当する複数クラスを管理できる。

生徒の基本情報：

* 出席番号
* 氏名

CSV/Excelからの一括登録と手入力の両方を想定する。

MVPではCSVを標準とし、Excel直接読み込みは将来拡張可能とする。

---

# 6. Course Management

授業を登録できる。

例：

* 情報Ⅰ
* 情報探究
* 選択情報

1つのCourseに複数クラスの生徒を登録できる。

---

# 7. Timetable

曜日・時限ごとに授業を登録する。

「今日の授業」画面では、現在の日付と時間割から当日の授業を表示する。

教師が毎回、

* 日付
* クラス
* 時限

を手入力する必要をなくす。

---

# 8. Lesson Session

実際に行われた授業をLessonSessionとして保存する。

LessonSessionには、

* 日付
* 時限
* Course
* 参加生徒
* 席配置
* グループ
* 出欠
* 評価
* 教師メモ

を関連付ける。

---

# 9. Seating

20～50席を扱える。

座席は自由にドラッグして配置できる。

座席には以下を表示可能。

* 座席番号
* 出席番号
* 氏名
* グループ名
* グループカラー
* 出欠状態

---

# 10. Seating Layouts

最低2種類のレイアウトを提供する。

### Normal Layout

通常授業用。

### Group Layout

グループ活動用。

両者は独立して保存する。

---

# 11. Layout Objects

最低限、以下のオブジェクトを配置できる。

* 座席
* 黒板
* ホワイトボード
* 教卓
* 教員PC
* テキスト

過剰な図形編集機能はMVPでは実装しない。

---

# 12. Groups

最大20種類のグループカラーを使用できる。

各カラーにグループ名を設定できる。

例：

* 赤 → A班
* 青 → B班
* 緑 → C班

グループメンバー一覧を表示する。

---

# 13. Random Grouping

グループをランダム編成できる。

指定可能な条件：

* グループ数
* 1グループ人数
* 禁止ペア
* 同じグループにしたいペア
* 前回同じグループだった生徒を避ける

欠席者は原則として自動編成対象から除外する。

---

# 14. Seating Shuffle

条件付きランダム席替えを提供する。

条件例：

* 前回と同じ席を避ける
* 特定生徒同士を離す
* 特定生徒同士を近づける
* 前方優先
* 後方優先
* 前回近かった生徒を避ける
* 前回同じグループだった生徒を避ける

条件には優先順位を設定できる。

---

# 15. Teacher / Student Display Separation

教師用画面と生徒向け表示画面を分離する。

教師には、

* 席替え条件
* 制約
* 優先順位
* アルゴリズム結果

を表示する。

生徒向け表示には、

* 席替え演出
* 新しい席

のみを表示する。

生徒に教師側の制約条件を表示してはいけない。

---

# 16. Attendance

授業ごとに出欠を記録する。

状態：

* 出席
* 欠席
* 遅刻
* 早退
* 公欠
* 忌引
* その他

席図から入力できる。

一覧画面からも入力できる。

---

# 17. Attendance Summary

別画面で、

* 生徒別
* クラス別
* 期間別

の集計を確認できる。

---

# 18. Evaluation

評価は「授業中の行動記録」を目的とする。

評価項目は固定しない。

授業ごとに評価項目セットを設定できる。

例：

### 情報Ⅰ

* 発言
* 課題への取り組み
* グループ活動
* 振り返り

### プログラミング

* コード理解
* デバッグ
* 課題達成
* 協働

---

# 19. Evaluation Types

評価項目ごとに評価方式を設定できる。

例：

* チェック
* ◎○△
* 数値
* 提出／未提出
* カスタム選択肢

---

# 20. Evaluation Input

授業中の操作を最小化する。

基本状態から該当生徒だけを変更する操作を優先する。

席図から生徒をクリックして評価を入力できる。

---

# 21. Student Profile

生徒をクリックすると、生徒カルテを表示する。

表示内容：

* 出席番号
* 氏名
* 出欠集計
* 評価集計
* 最近の授業履歴
* 教師メモ

---

# 22. Teacher Memo

教師が生徒について自由記述メモを保存できる。

メモには、

* 作成日時
* 更新日時
* 生徒
* 必要に応じて授業

を関連付ける。

---

# 23. Printing

A4横印刷を標準とする。

通常授業用席図とグループ活動用席図を別々に印刷できる。

印刷内容には、

* 年度
* 授業名
* クラス
* 日付
* 時限
* 席図

を含める。

---

# 24. CSV

以下をCSV出力可能とする。

* 生徒一覧
* 出欠
* 評価
* 授業履歴
* グループ履歴
* 席配置履歴

---

# 25. Backup

全データを1つのバックアップファイルとして保存できる。

バックアップには、

* schemaVersion
* appVersion
* createdAt
* schoolYear
* data

を含める。

復元時にはデータ検証を行う。

---

# 26. Offline Requirement

以下の機能はオフラインで利用可能でなければならない。

* 生徒管理
* クラス管理
* 授業
* 席図
* 出欠
* 評価
* グループ
* 席替え
* 印刷
* CSV
* バックアップ
* 復元

外部APIやクラウドDBへの接続を必須にしない。

---

# 27. Security

生徒データを外部へ送信しない。

GitHubリポジトリに実際の生徒データを保存しない。

生徒名簿、出欠、評価、教師メモなどはローカルデータとして管理する。

将来的なPINロックに対応できる設計にする。

---

---

# 29. Development Principles

1. いきなり全機能を実装しない。
2. Phase単位で実装する。
3. 仕様書をSource of Truthとする。
4. 履歴データを破壊しない。
5. 外部サービスを必須にしない。
6. 授業中の操作速度を最優先する。
7. 型安全性を維持する。
8. 各Phaseでテストする。
9. 小さなGit Commitを作る。
10. 不明確な重要要件は実装前に確認する。

---

# 30. Success Criteria

教師が、

今日の授業
→ 授業開始
→ 席図確認
→ 生徒選択
→ 出欠／評価
→ グループ活動
→ 席替え
→ 授業終了

という流れを、授業を止めずに実行できること。

ClassSeat Managerの最優先価値は「多機能さ」ではなく「授業中の使いやすさ」である。
